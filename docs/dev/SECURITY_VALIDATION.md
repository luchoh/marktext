# Security Validation

Use this checklist after changes to renderer isolation, sanitization, diagram rendering, export rendering, updater behavior, or local-link handling.

## Automated Checks

Run these from the repo root:

```bash
devenv shell -- node tools/checkSecurity.js
devenv shell -- ./node_modules/.bin/playwright test -c test/e2e/playwright.config.js test/e2e/xss.spec.js test/e2e/diagram.spec.js
devenv shell -- cross-env NODE_ENV=test ELECTRON_DISABLE_SECURITY_WARNINGS=true karma start test/unit/karma.conf.js --single-run
```

What they cover:

- `tools/checkSecurity.js`: renderer isolation and BrowserWindow regression checks.
- `xss.spec.js`: malicious raw HTML and diagram preview hardening.
- `diagram.spec.js`: PlantUML preview through the preload bridge.
- Karma unit suite: sanitizer regressions, export sanitization, and parser coverage.

## Manual Preview Pass

Open each fixture in a packaged/dev Electron build:

- `test/e2e/data/xss.md`
- `test/e2e/data/xss-diagrams.md`
- `test/e2e/data/plantuml.md`

Verify:

1. The app starts without a main-process crash dialog.
2. The editor window is not blank and the loading overlay clears.
3. `xss.md` does not execute active HTML content.
4. `xss-diagrams.md` renders preview content without leaving active SVG/HTML nodes behind.
5. `plantuml.md` renders a PlantUML preview image or a broken remote image placeholder, but never falls back to executable HTML/JS.

## Manual Export Pass

For `test/e2e/data/xss.md`, `test/e2e/data/xss-diagrams.md`, and `test/e2e/data/plantuml.md`:

1. Export to styled HTML from the app UI.
2. Inspect the exported file with:

```bash
rg -n '<script|<iframe|<foreignObject|on[a-z]+=|javascript:' /path/to/exported.html
```

Expected result: no matches.

For PlantUML exports, also confirm the output contains a fixed-host PlantUML image URL:

```bash
rg -n 'https://www\\.plantuml\\.com/plantuml/svg/~1' /path/to/plantuml-export.html
```

Expected result: one match.

## Network Caveat

PlantUML rendering is intentionally routed through a fixed remote `https://www.plantuml.com/plantuml/svg/~1...` image URL generated by the preload bridge.

If a local firewall such as Little Snitch blocks `www.plantuml.com`, preview/export may show a broken image. That is acceptable for this validation pass. The important invariants are:

1. MarkText does not crash.
2. The renderer does not regain Node access.
3. No attacker-controlled HTML/SVG executes in preview or export output.
